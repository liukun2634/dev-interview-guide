# 程序员面试手册 — 文档页统一设计方案

## 1. 背景

当前站点已经具备首页、顶部导航、侧边栏、正文页等基础能力，但整体体验仍存在以下问题：

- 首页、导航、正文的视觉气质不完全一致
- 主题样式存在多套方向并存的问题，品牌感不够集中
- 页面已经“能看”，但还没有形成“可信、统一、值得收藏”的产品感
- 正文阅读体验已有基础，但层次、节奏、重点信息的表现仍可进一步收敛

这次改造不是做增长首页，也不是重写内容，而是完成一次纯设计系统层面的统一升级。

## 2. 本轮目标

本轮只做两件事：

1. **统一全站设计语言**
2. **提升正文与页面阅读体验**

目标效果：

- 让首页、导航、侧栏、正文属于同一个产品
- 让页面第一感受更专业、更可信
- 让长文阅读更稳定、更耐读
- 让现有内容在不改写的前提下，看起来更有整理感与完成度

## 3. 非目标

本轮明确不做：

- 内容结构改写
- 文章文案优化
- 首页增长模块
- 热门专题位、推荐阅读位、最近更新位
- 相关文章分发
- 强运营化曝光设计
- 推荐系统或复杂内容编排逻辑

## 4. 目标用户

本轮的主目标用户是：**面试冲刺型用户**。

他们最看重的不是花哨感，而是：

- 内容是否专业可信
- 页面是否有秩序感
- 是否容易快速定位和继续阅读
- 是否值得收藏，作为长期复习资料

因此视觉策略必须优先服务“可信感”，再服务“可读性”，而不是先做强刺激点击。

## 5. 设计定位

本次统一设计采用以下定位：

- **骨架**：专业知识库
- **正文**：阅读型强化
- **首页**：克制的入口页，而不是增长首页
- **整体气质**：可信、克制、耐读、统一

不追求营销感，不追求炫技，而是做成一个：

> **带一点编辑感的专业面试知识库。**

## 6. 设计原则

### 6.1 统一优先

首页、顶部导航、侧边栏、正文页、卡片、标签、代码块、提示块必须属于同一套语言。

统一项包括：

- 色彩体系
- 字体体系
- 圆角体系
- 边框与阴影体系
- 间距节奏
- 激活态与 hover 规则

### 6.2 可信优先

第一眼要让用户觉得站点内容被认真整理过，而不是简单拼装出的主题站。

表现方式：

- 控制颜色数量
- 控制装饰密度
- 强调秩序感与版式稳定性
- 弱化无必要的动画和花哨效果

### 6.3 阅读优先

正文页是核心价值区。设计必须让长文阅读更舒服。

表现方式：

- 稳定的标题层级
- 明确的段落节奏
- 统一的代码块和表格样式
- 高质量重点信息块
- 清晰但不过强的目录辅助

### 6.4 组件服务内容

卡片、标签、提示块、导航控件都不是装饰，而是内容理解工具。

所有组件都应帮助用户：

- 识别结构
- 判断重点
- 减少认知负担
- 更顺畅地进入正文

## 7. 视觉语言

### 7.1 色彩系统

全站只保留一套主色和一套中性色体系。

建议方向：

- **主色**：深青 / 墨绿蓝方向
- **中性色**：温和、偏暖或偏中性的阅读底色与边框色

色彩规则：

- 主色只用于链接、激活态、重点标签、关键入口
- 中性色承担页面主体面积
- 避免首页、正文、组件各用一套强调色
- 避免多主色并存造成风格漂移

### 7.2 字体系统

采用三段式结构：

- **标题字体**：有一定识别度与气质
- **正文字体**：高可读、中文表现稳定
- **等宽字体**：代码、标签、元信息统一使用

使用规则：

- 首页标题、正文 h1/h2、卡片标题使用统一标题逻辑
- 正文、列表、表格、说明文字使用统一正文逻辑
- 标签、难度、辅助信息使用统一辅助文字逻辑

### 7.3 间距系统

统一页面节奏，建立“被编辑过”的观感。

需统一的层级：

- 页面外边距
- 模块间距
- 标题与正文之间的距离
- 列表项、表格、代码块、提示块的上下留白
- 卡片内部信息的垂直节奏

### 7.4 圆角与边框

整体采用：

- **轻圆角**
- **细边框**
- **弱阴影或无阴影**

交互态优先通过以下变化完成：

- 边框色变化
- 背景色轻微变化
- 轻微位移或非常克制的阴影

避免厚重投影和过强悬浮感。

## 8. 页面结构设计

## 8.1 首页

首页本轮不做增长模块，只承担三件事：

- 建立品牌信任
- 告诉用户站点覆盖范围
- 将用户顺滑送入分类正文

建议首页结构：

1. **品牌头部**
   - 站点名称
   - 一句可信的副标题
   - 简洁说明站点适用人群和价值

2. **核心分类入口**
   - 9 大领域统一卡片入口
   - 可保留一个轻重点分类，但不做强运营化放大

3. **内容价值说明**
   - 强调系统化、知识整理、面向面试场景

首页定位应从“分类列表页”升级为“可信入口页”。

## 8.2 顶部导航

顶部导航承担：

- 品牌识别
- 当前知识域感知
- 快速跨域跳转

建议结构：

- 左侧：品牌
- 中间：当前栏目 / 分类切换
- 右侧：搜索与外部入口

重点不是加更多功能，而是让头部成为稳定、精致、统一的产品框架。

## 8.3 侧边栏

侧边栏应被定义为“当前知识域的阅读导航”，而不是普通折叠控件。

优化方向：

- 当前分类信息更明确
- 分类切换与文章目录分层更清晰
- 一级组标题识别感更稳定
- 当前文章高亮更像阅读定位，而不是普通链接激活态

## 8.4 正文页

正文页是本轮改造的核心。

目标：

- 不改内容本身
- 提升结构感、重点感、节奏感
- 让长文更耐读

建议正文页形成以下层级：

1. **页头区**
   - 标题
   - 简短引导描述或分类感知
   - 可选 metadata 区域

2. **正文区**
   - 标题层级统一
   - 列表、表格、代码块、提示块样式统一
   - 重点信息块具有明确识别度

3. **右侧目录区**
   - 更像阅读导航，而不是单纯锚点列表

4. **页尾区**
   - 本轮仅保留基本前后文关系，不扩展推荐分发

## 9. 共用组件规范

### 9.1 卡片系统

首页卡片、分类入口卡片、其他内容型卡片必须统一为一个家族。

统一项包括：

- 标题字号与字重
- 描述行数和长度控制
- 图标尺寸与位置
- badge 样式
- hover 行为
- 箭头或入口提示方式

设计原则：卡片是内容入口，不是装饰物。

### 9.2 标签系统

标签只承担辅助判断作用，不能喧宾夺主。

可保留的标签类型：

- 分类
- 难度
- 高频 / 热门
- 面试重点

规则：

- 统一尺寸
- 统一边框和底色策略
- 统一辅助信息层级
- 避免颜色过多和视觉噪音

### 9.3 强调块 / 知识块

建议将正文中的特殊信息收敛为 2-3 套核心组件：

- **重点总结块**
- **高频问题块**
- **补充说明块**

这类组件是建立“知识整理感”的关键，不应只是默认 Markdown 提示框的轻度换皮。

### 9.4 代码块与表格

代码块和表格是技术站可信感的重要来源。

要求：

- 统一背景、边框、圆角、语言标签、复制按钮逻辑
- 行内 code 统一风格
- 表格统一表头层级、行高、hover 反馈
- 避免过度装饰，技术感来自秩序而不是视觉花样

## 10. 主题方向建议

现有多套样式中，建议采用以下融合方向：

- 保留阅读型主题里更强的阅读气质
- 保留文档型主题里更强的结构清晰度
- 去掉风格混杂与主题漂移

最终目标不是完全贴近任何现成模板，而是形成一个独立的方向：

> **比 GitHub Docs 更有阅读感，比杂志风更克制。**

## 11. 落地范围

本轮实施应覆盖以下区域：

- 首页
- 顶部导航
- 侧边栏
- 正文页
- 卡片
- 标签
- 提示块 / 知识块
- 代码块
- 表格
- 目录区

## 12. 验收标准

完成后应满足以下标准：

1. 首页、导航、侧栏、正文页看起来属于同一产品
2. 页面视觉语言收敛为一套稳定规则，无明显风格混杂
3. 正文页长文阅读更舒适，标题与段落层次更清晰
4. 卡片、标签、提示块、代码块都形成统一组件语言
5. 首页保持克制，不出现增长模块或强运营化设计
6. 在不改内容的前提下，整体页面更专业、更可信、更有完成度

## 13. 后续实现建议

实现顺序建议为：

1. 先统一设计 token（颜色、字体、边框、圆角、间距）
2. 再统一导航与侧栏
3. 再统一正文页元素（标题、段落、代码块、表格、提示块）
4. 最后收口首页卡片与入口区

这样可以先建立底层一致性，再完成页面级统一。
