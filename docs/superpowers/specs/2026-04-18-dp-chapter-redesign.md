# 动态规划章节重新设计

## 目标

重新规划动态规划（DP）章节，使读者能够系统掌握所有 DP 题型的通用思考方法。重点不是堆砌题解，而是建立"拿到任何 DP 题都知道怎么想"的思维框架。

## 设计原则

1. **框架优先**：每个类型先讲通用思考逻辑，再看具体题目
2. **一题精讲**：每个类型选 1 道最典型的题做完整教学（状态定义 → 转移推导 → 初始化 → 遍历顺序 → 代码 → 复杂度）
3. **延伸题点拨**：其余题目给 LeetCode 链接 + 一句话说明与典型题的区别 + 需要注意的技巧
4. **代码语言**：Java
5. **文件数量**：7 个文件（含 index），适当合并相关类型

## 每篇统一结构

```
1. 识别信号 — 什么样的题属于这个类型？关键词是什么？
2. 通用思考框架（详细）
   - 如何定义状态（dp 数组代表什么）
   - 如何推导转移方程（从哪些子问题来、决策是什么）
   - 初始化与边界处理
   - 遍历顺序的选择逻辑
   - 空间优化的可能性
3. 典型例题完整讲解（1 道）
   - 题目描述
   - 思考过程（按框架一步步展开）
   - Java 代码实现
   - 复杂度分析
4. 延伸题目表
   | 题目 | 链接 | 与典型题的区别 | 关键技巧 |
5. 常见陷阱与调试技巧
```

## 文件规划

### 1. `index.md` — DP 总论与解题方法论

**定位**：整个 DP 章节的入口，不讲具体题型，只讲通用方法论。

**内容**：

1. **什么是动态规划**
   - 核心本质：把一个问题拆成重叠的子问题，每个子问题只算一次
   - 与贪心的区别：贪心做局部最优选择不回头，DP 考虑所有子问题的最优组合
   - 与分治的区别：分治的子问题不重叠，DP 的子问题大量重叠
   - 两个前提条件：重叠子问题 + 最优子结构

2. **如何识别 DP 题**
   - 题目问"最大/最小/最长/最短" → 可能是最优化 DP
   - 题目问"有多少种方式/方案" → 可能是计数 DP
   - 题目问"是否可能/能否达到" → 可能是可行性 DP
   - 暴力递归画出递归树，发现大量重复节点 → 确认是 DP

3. **解题五步法**（核心，要详细展开每一步的思考逻辑）
   - **第一步：定义状态** — 用自然语言说清楚 `dp[i]`（或 `dp[i][j]`）代表什么。技巧：先想"我需要哪些信息才能做出当前决策"，这些信息就是状态的维度
   - **第二步：推导转移方程** — 问自己"dp[i] 可以从哪些更小的状态得到？做了什么决策？"。画出从 dp[i-1]、dp[i-2] 等到 dp[i] 的箭头
   - **第三步：确定初始化** — 找到最小的、不能再拆的子问题，直接给值。常见错误：忘记初始化、初始化值错误
   - **第四步：确定遍历顺序** — 原则：计算 dp[i] 时，它依赖的状态必须已经算好。从转移方程的依赖关系反推遍历方向
   - **第五步：确定返回值** — 不一定是 dp[n]，可能是 dp 数组中的最大值，或者 dp[m][n]

4. **自顶向下 vs 自底向上**
   - 记忆化递归（自顶向下）：直觉自然、容易写，但有递归栈开销
   - 递推表（自底向上）：性能更优、方便空间优化，但需要想清楚遍历顺序
   - 选择建议：先用记忆化递归理清思路，面试中用递推表实现

5. **空间优化技巧**
   - 观察转移方程的依赖范围：只依赖上一行 → 两行滚动；只依赖前两个 → 两个变量
   - 一维压缩的遍历方向：0/1 背包倒序、完全背包正序的原理
   - 何时不优化：状态需要回溯路径时保留完整 dp 表

6. **常见错误与调试方法**
   - 状态定义模糊 → 打印 dp 表检查每个值是否符合定义
   - 初始化遗漏 → 手算前几个值对照
   - 遍历顺序错误 → 检查是否用到了还没算的状态
   - Off-by-one → 明确 dp 数组长度是 n 还是 n+1

7. **DP 题型全景图** — 简要列出后续各篇，帮读者建立整体认知地图

**贯穿示例**：用爬楼梯（LC 70）演示五步法的完整过程，不作为独立题解，而是方法论的教学载体。

### 2. `linear-dp.md` — 线性 DP + 网格 DP

**通用思考框架（线性 DP）**：
- 识别信号：输入是一维数组/序列，每个位置做一个决策，答案随位置线性推进
- 状态定义套路：`dp[i]` = 考虑到第 i 个元素时的最优解/方案数
- 转移方程套路：`dp[i]` 依赖 `dp[i-1]`（或 `dp[i-1]`, `dp[i-2]`，或 `dp[0..i-1]` 中满足条件的）
- 决策模型：选或不选当前元素 / 从哪个前驱转移过来
- 空间优化：大多可压缩到 O(1) 或 O(k)

**典型例题**：打家劫舍 LC 198（选/不选模型的最佳教学载体）

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 爬楼梯 LC 70 | 最基础的线性 DP，两个前驱 |
| 打家劫舍 II LC 213 | 环形 → 拆成两个线性子问题 |
| 最大子数组和 LC 53 | dp[i] 定义变化：必须以 i 结尾；Kadane 算法 |
| 解码方法 LC 91 | 条件转移：需要判断单字符/双字符是否合法 |
| 跳跃游戏 LC 55 / II LC 45 | 可行性/最优化双变体 |

**通用思考框架（网格 DP）**：
- 识别信号：在二维矩阵上从某点到某点，求最优路径/方案数
- 状态定义套路：`dp[i][j]` = 到达 (i,j) 的最优解/方案数
- 转移方程套路：`dp[i][j]` 来自 `dp[i-1][j]` 和 `dp[i][j-1]`（或更多方向）
- 关键技巧：第一行/第一列的初始化、障碍物处理、反向 DP

**典型例题**：最小路径和 LC 64

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 不同路径 LC 62 / II LC 63 | 计数型 + 障碍物处理 |
| 地下城游戏 LC 174 | 反向 DP：从终点往起点推 |
| 最大正方形 LC 221 | dp[i][j] 含义变化：以 (i,j) 为右下角的最大正方形边长 |

### 3. `knapsack-dp.md` — 背包 DP

**通用思考框架**：
- 识别信号：一组物品 + 容量限制 + 求最优/计数/可行性
- 核心思维：每个物品面临"选几个"的决策，按物品顺序逐个考虑
- **0/1 背包模板**：每件物品最多选 1 次
  - 状态：`dp[j]` = 容量为 j 时的最大价值
  - 转移：`dp[j] = max(dp[j], dp[j - w[i]] + v[i])`
  - 关键：**一维时倒序遍历容量**，保证每件物品只用一次
- **完全背包模板**：每件物品可选无限次
  - 与 0/1 唯一区别：**正序遍历容量**
  - 为什么正序：允许同一物品被重复选取
- **如何判断用哪种背包**：物品能否重复使用 → 0/1 vs 完全
- **三种问法的转移差异**：
  - 最优化：`max` / `min`
  - 计数：`+=`
  - 可行性：`||`

**典型例题**：分割等和子集 LC 416（0/1 背包可行性，最直观展示背包建模过程）

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 目标和 LC 494 | 0/1 背包计数变体，需要数学转换：sum(P) = (target + total) / 2 |
| 零钱兑换 LC 322 | 完全背包求最小值，注意初始化为 INF |
| 零钱兑换 II LC 518 | 完全背包计数，注意与排列数（LC 377）的区别：外层物品 vs 外层容量 |
| 一和零 LC 474 | 二维费用 0/1 背包，两个容量维度 |
| 多重背包 | 每件物品有数量上限，二进制拆分优化 |
| 分组背包 | 每组只能选一件，多一层组内枚举 |

### 4. `sequence-dp.md` — 序列与回文 DP

**通用思考框架（子序列/双串 DP）**：
- 识别信号：两个字符串/数组的匹配、比较、变换；或单序列的子序列问题
- 状态定义套路：
  - 单串：`dp[i]` = 以第 i 个元素结尾（或前 i 个元素）的最优解
  - 双串：`dp[i][j]` = 串 A 前 i 个字符与串 B 前 j 个字符的最优解
- 转移方程推导逻辑：**看最后一个元素的匹配情况**
  - 匹配（`A[i] == B[j]`）→ 从 `dp[i-1][j-1]` 转移
  - 不匹配 → 从 `dp[i-1][j]`、`dp[i][j-1]`、`dp[i-1][j-1]` 中选最优
- 关键区分："子序列"可以不连续 vs "子数组"必须连续 → 转移方程不同
- 路径回溯：编辑距离等题需要回溯操作序列时，保留完整 dp 表 + 反向追踪

**典型例题**：编辑距离 LC 72（双串 DP 的最佳教学题，三种操作对应三个转移方向）

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 最长递增子序列 LC 300 | 单串 dp[i] = 以 i 结尾的 LIS 长度；进阶：贪心+二分 O(n log n) |
| 最长公共子序列 LC 1143 | 双串标准模板，匹配/不匹配两路转移 |
| 不同的子序列 LC 115 | 计数型双串 DP，只能删不能增 |
| 最长重复子数组 LC 718 | 与 LCS 对比：不匹配时 dp=0（连续要求） |

**通用思考框架（回文 DP）**：
- 识别信号：回文相关的最优/计数/判定问题
- 两种状态定义：
  - `dp[i][j]` = 子串 s[i..j] 是否为回文 / 的最长回文长度
  - `dp[i][j]` = 将 s[i..j] 变成回文需要的最少操作
- 转移逻辑：**从两端向中间收缩**，看 `s[i]` 和 `s[j]` 是否相等
- 遍历顺序关键：**长度从短到长**（先算短区间，再算长区间），或反向遍历 i
- 与中心扩展法的对比：DP 适合需要所有子串回文信息的题，中心扩展适合只求最长

**典型例题**：最长回文子序列 LC 516

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 最长回文子串 LC 5 | 子串（连续）vs 子序列（不连续），也可用中心扩展 |
| 回文分割 II LC 132 | 两层 DP：先预处理回文判定表，再求最少分割次数 |

### 5. `interval-and-state-machine-dp.md` — 区间 DP + 状态机 DP

**通用思考框架（区间 DP）**：
- 识别信号：答案与一个**区间**相关，大区间的答案由小区间合并/分割得到
- 状态定义：`dp[l][r]` = 区间 [l, r] 上的最优解
- 转移思维：**枚举分割点 k**，将 [l, r] 拆成 [l, k] 和 [k+1, r]
  - 或者考虑"最后一次操作"作用在哪个位置
- 遍历顺序：**区间长度从小到大**（len = 1, 2, ..., n），保证小区间先算好
- 初始化：长度为 1 的区间（单个元素）
- 时间复杂度：通常 O(n³)

**典型例题**：戳气球 LC 312（"最后一次操作"的逆向思维典范）

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 石子合并 | 经典合并型区间 DP，分割点枚举 |
| 多边形三角剖分 LC 1039 | 三角形划分，注意环形处理 |

**通用思考框架（状态机 DP）**：
- 识别信号：每个时刻处于某个"状态"，不同状态之间有转移规则
- 核心思维：**先画状态转移图**，节点是状态，边是合法转移，边上标注代价
- 状态定义：`dp[i][s]` = 第 i 天处于状态 s 时的最优解
- 转移方程：按状态图的边写出所有合法转移
- 建模技巧：把隐含的约束条件（冷冻期、次数限制、手续费）建模为状态维度或转移代价
- 股票系列的统一框架：
  - 状态：持有/不持有（+ 冷冻期/交易次数作为额外维度）
  - 所有股票题都是这个框架的特例

**典型例题**：买卖股票含冷冻期 LC 309（三状态转移图最能体现状态机思维）

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 买卖股票 I LC 121 | 只交易一次，可简化为维护前缀最小值 |
| 买卖股票 II LC 122 | 无限次交易，两状态即可 |
| 买卖股票 III LC 123 | 最多 2 次 → 增加交易次数维度 |
| 买卖股票 IV LC 188 | 最多 k 次，III 的泛化 |
| 含手续费 LC 714 | 转移时减去手续费即可 |

### 6. `tree-dp.md` — 树形 DP

**通用思考框架**：
- 识别信号：在树结构上求最优/计数，答案依赖子树信息
- 核心思维：**后序遍历 + 从子节点向父节点汇聚信息**
- 状态定义思路：
  1. 问自己：对于当前节点，我需要知道什么信息才能向父节点汇报？
  2. 这些信息就是状态。常见：选当前节点 / 不选当前节点
- 转移方程：当前节点的 dp 值 = f(左子的 dp 值, 右子的 dp 值)
- 返回值 vs 全局答案：
  - 返回给父节点的值 ≠ 最终答案（如路径和问题，最优路径可能不经过根）
  - 技巧：用全局变量在遍历过程中维护答案
- 实现方式：递归函数返回状态数组/元组

**典型例题**：打家劫舍 III LC 337（选/不选 + 后序遍历，树形 DP 入门首选）

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 二叉树最大路径和 LC 124 | 返回值（单边路径）vs 全局答案（可能拐弯）的区分 |
| 二叉树直径 LC 543 | 与 124 类似但计算边数而非节点值 |
| 监控二叉树 LC 968 | 三状态（有相机/被覆盖/未覆盖），贪心+树形 DP |

### 7. `advanced-dp.md` — 状压 DP + 计数 DP

**通用思考框架（状压 DP）**：
- 识别信号：元素个数很少（n ≤ 20），需要追踪"哪些元素已被选过"
- 核心思维：用一个 **n 位二进制整数**表示集合状态，第 k 位为 1 表示第 k 个元素已选
- 状态定义：`dp[mask]` 或 `dp[mask][i]`
  - mask = 已选元素集合
  - i = 当前位置（如旅行商问题）
- 转移：枚举下一个要选的元素 j（要求 j 不在 mask 中）
- 常用位运算：
  - 检查第 k 位：`(mask >> k) & 1`
  - 设置第 k 位：`mask | (1 << k)`
  - 枚举子集：`for (int sub = mask; sub > 0; sub = (sub - 1) & mask)`
- 复杂度：O(2ⁿ × n) 或 O(2ⁿ × n²)，n > 20 就不适用

**典型例题**：最短 Hamilton 路径（状压 DP 最经典的教学题）

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 火柴拼正方形 LC 473 | 状态表示哪些火柴已用，需要剪枝优化 |
| 漂亮排列 LC 526 | 排列型状压，mask 表示已放置的数字集合 |

**通用思考框架（计数 DP）**：
- 识别信号：求方案数、组合数、构造方式的数量
- 与最优化 DP 的区别：转移用 `+=` 而非 `max/min`
- 关键注意点：
  - **组合 vs 排列**：外层枚举物品 → 组合数（LC 518）；外层枚举容量 → 排列数（LC 377）
  - 初始化：`dp[0] = 1`（空集/零容量有 1 种方案）
  - 避免重复计数：明确枚举顺序
- 与数学方法的对比：小规模用 DP，大规模可能需要组合数学 + 取模

**典型例题**：不同的二叉搜索树 LC 96（Catalan 数，DP 建模 + 数学对照）

**延伸题目表**：
| 题目 | 区别与关键技巧 |
|------|---------------|
| 完全平方数 LC 279 | 完全背包求最小值，也可用 BFS |
| 组合总和 IV LC 377 | 排列型计数，注意与 LC 518 的遍历顺序差异 |
| 整数拆分 LC 343 | 枚举第一刀的位置，max(j*(i-j), j*dp[i-j]) |
