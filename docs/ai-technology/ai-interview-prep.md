# AI 时代面试准备策略

<span class="dig-tag dig-tag--category">面试准备</span> <span class="dig-tag dig-tag--easy">⭐ 入门</span> <span class="dig-tag dig-tag--hot">🔥🔥🔥 高频</span>

::: tip 💡 核心要点（2026 版）
部分岗位已提高对“AI 协作能力 + 原理判断力 + 工程实战”的关注，但公司、地区、岗位和面试轮次差异很大。不要假设面试官默认所有人会 Cursor、Copilot 或 Claude Code；应先确认是否允许使用 AI，并同时准备**怎么用 AI**、**AI 出错时怎么办**、**没有 AI 时能否独立完成核心任务**。
:::

## 2026 年面试的 6 大新趋势（必知）

下面是 2024-2026 年在部分招聘流程和岗位描述中可观察到的方向，不代表统一行业规则；准备时应以目标公司的最新职位描述、招聘通知和面试官说明为准：

| 变化 | 老规则（2023 之前） | 新规则（2025-2026） |
|------|-------------------|-------------------|
| **知识题权重** | 偏重概念记忆 | 部分岗位增加原理追问、真实工程任务和调试 |
| **现场编程** | 算法题为主 | 算法题仍常见；部分流程增加工程任务或允许 AI 协作 |
| **系统设计** | 高并发秒杀/短链 | **新增 RAG / Agent / LLM 推理服务**设计题 |
| **AI 工具考察** | 通常不涉及 | AI 相关或工程效率岗位可能询问工具、验证方法和边界 |
| **面试完整性** | 传统监考 | 可能共享屏幕、禁用粘贴或要求口头解释，规则以通知为准 |
| **项目深挖** | 问你做了什么 | **问 AI 做了什么 vs 你做了什么**、AI 写的代码你能否独立 review/debug |

::: warning ⚠️ 最大的认知误区

> **"AI 能搜到的我就不用理解了"** —— 风险很大。除非面试规则明确允许，否则按不能使用外部 AI 准备。AI 应该帮助你更快建立体系并理解原理，不是替你形成判断力。能讲清 HashMap 扩容机制和能 prompt 出答案，是两个不同的能力维度。

:::

## AI 协作能力 — 2026 面试新考点

若目标岗位考察 AI 协作，常见问题之一是：“你怎么用 AI 提升日常开发效率？”高质量回答应包含**具体工具 + 真实场景 + 可复现度量 + 验证方法 + 局限性认识**。

### 常见工具类别（按岗位选学）

| 类别 | 推荐 | 用途 |
|------|------|------|
| **IDE 代码助手** | **Cursor** / GitHub Copilot / Windsurf | 行内补全、多文件改造、聊天 |
| **Agent 编码** | **Claude Code** / Cursor Agent / Cline / Copilot agent mode | 多文件实现、调试与验证 |
| **通用对话** | 当前可用的 Claude / GPT / Gemini 等模型 | 架构讨论、原理讲解、代码 Review |
| **本地模型** | Ollama + 适配硬件的开放权重模型 | 隐私场景、离线实验 |
| **代码 Review** | CodeRabbit / GitHub Copilot Review | PR 自动审查 |
| **文档/知识库** | NotebookLM / Cursor @Docs | 灌入文档做 RAG 问答 |

### AI 协作 5 大能力梯度（自测）

| 等级 | 能力描述 | 面试评价 |
|------|---------|---------|
| **L1 抄答案** | 让 AI 写代码，复制粘贴运行 | ❌ 减分项 |
| **L2 会问** | 知道怎么提供上下文、追问细节 | 入门 |
| **L3 会判断** | AI 写错时能识别、能修、能解释为什么错 | 中级 |
| **L4 会架构** | 把大任务拆成 AI 能高质量完成的子任务 | 高级 |
| **L5 会评估** | 知道哪些任务 AI 不擅长（复杂状态/隐式约束/性能调优）| 资深 |

### 现场 AI 协作题（练习示例）

> **题目**：用 Cursor / Claude Code，在 30 分钟内实现一个 "URL 短链服务"，要求支持：① 短码生成（≤ 6 位）；② 防止重复；③ 访问统计。面试官全程**共享屏幕**观察，过程中可以问任何问题。
>
> **考察点**：
> ① **会不会先列需求/写测试** —— 直接让 AI "写一个短链服务" 是低分答案；
> ② **会不会做约束** —— "用 Base62 编码 + 雪花 ID" 比 "你帮我想个方案" 高分；
> ③ **AI 生成完代码后做什么** —— 直接运行 = 低分，逐行 review + 加边界测试 = 高分；
> ④ **能不能讲清原理** —— "为什么 Base62 而不是 Base64？" 能答出 URL 安全字符就 OK；
> ⑤ **能不能识别 AI 的坑** —— 模型可能生成“看起来对但漏处理碰撞”的代码，能用测试和审查发现 = 加分。

### 必背答题模板（AI 协作类问题）

> **面试官：你怎么用 AI 工具？提升了多少效率？踩过什么坑？**
>
> **答**：分场景说效率：
> ① **样板代码**（CRUD / DTO / Mapper）：说明自己在若干任务上的基线耗时与使用后耗时；
> ② **新框架/新库**：让 AI 列典型示例和风险，再用官方文档与最小实验核验；
> ③ **复杂业务逻辑**：展示 AI 漏掉的边界条件，以及自己如何通过测试和 review 修正；
> ④ **性能调优 / 分布式一致性**这种**需要全局上下文**的问题，AI 经常给似是而非的建议，**我只把它当"列举可能方向"用，不直接采纳**。
> 踩坑部分必须讲自己的真实案例：具体任务、模型哪里错了、你用什么证据发现、如何修复，以及后来增加了什么测试或流程。不要套用虚构的生产事故。

## 5 大维度同步升级你的复习计划

### 维度 1：八股文 — 按岗位优先级取舍，留下“会被追问”的部分

**优先掌握能讲清原理、边界和取舍的主题**：HashMap 扩容、Synchronized 锁升级、JVM GC、Spring Bean 生命周期、MySQL B+ 树、Redis 持久化、CAP / Paxos / Raft、TCP 三握四挥、HTTP/HTTPS、I/O 模型。具体比例按岗位 JD 和面试反馈调整。

**砍掉**：Servlet 9 大生命周期、Spring 注解 30 条、HashMap put 流程"红黑树阈值是 8 数组长度 64"等纯记忆题——这些 AI 5 秒就能背给你听，面试官也知道。

### 维度 2：现场编程 — 算法基本功 + 工程任务都要练

| 老准备方式 | 新准备方式 |
|----------|----------|
| 只追求刷题数量 | 按目标岗位覆盖高频题型，并增加完整小项目（短链/限流/RAG 客服）|
| 背模板 | **能脱离 AI 写**：双指针/二分/DFS/DP 5 大模板必须自己手写 |
| 不练表达 | **边写边讲**（5 分钟讲清思路 + 5 分钟写代码 + 5 分钟答追问）|

::: tip 💡 关键转变

> 部分在线面试会共享屏幕或禁用粘贴，也可能明确禁止外部 AI。无论具体平台是什么，**手写双指针 / 二分边界 / 链表反转**等基本功都应能脱离辅助完成。

:::

### 维度 3：系统设计 — 必须懂 AI 系统

**2026 值得准备的 AI 系统题**：

| 题目 | 核心考察 |
|------|---------|
| **设计一个企业知识库（RAG）** | 文档切分 / Embedding / 向量库选型 / Rerank / Prompt 模板 / 评估 |
| **设计 ChatGPT 这类对话产品** | 流式输出 / KV Cache / 会话存储 / 多模态 / 速率限制 |
| **设计 Cursor 这类 Code Agent** | Diff Apply / 多文件上下文 / Tool Use / 长上下文 |
| **设计推理服务（vLLM/SGLang）** | Continuous Batching / PagedAttention / Tensor Parallel |
| **设计 Computer Use Agent** | 屏幕理解 / 动作空间 / 安全沙箱 / 失败恢复 |

详见 [AI 系统设计](./ai-system-design)、[RAG](./rag)、[Agent](./ai-agents)、[推理优化](./inference-optimization)。

### 维度 4：项目讲解 — "我做的 vs AI 做的" 必须分清

如果项目使用了 AI，面试官可能追问：“这个功能 AI 写了多少？你做了什么决策？”

**好的回答模板（STAR-AI）**：

> **S**ituation：项目背景 + 团队规模 + 我的角色
> **T**ask：要解决什么问题
> **A**ction：
>   - **架构设计是我做的**（讲清取舍）
>   - **样板代码借助 AI 完成**（填写自己的基线耗时、使用后耗时和样本数量）
>   - **核心算法是我手写的**（讲清边界）
>   - **AI 生成后我做了什么 review**（举具体的修正案例）
> **R**esult：量化效果（性能/成本/上线时间）

### 维度 5：行为面试 — 准备 3 个"AI 协作"故事

**至少准备 3 个具体故事**：
① **AI 帮我快速学会新东西**（X 周搞定原本需要 X 月的技术栈）
② **AI 出错我发现并修正**（具体哪个 bug、什么时候发现、为什么 AI 会错）
③ **判断 AI 不适用而坚持自己做**（例：性能调优 / 复杂分布式 / 业务领域知识）

## 用 AI 辅助复习的 4 个高效场景

### 场景 1：用 AI 做知识诊断

```text
我准备面试全栈工程师岗位（Java + Spring Boot + React），目标公司是国内大厂。
请针对以下方向各出 3 道 2026 年大厂真实考过的题目，只出题不给答案：
1. Java 并发与 JVM
2. Spring 原理与 Spring AI
3. React 18+ 与 RSC
4. 数据库与分布式事务
5. 系统设计（含 AI 系统）
另外请直接判断："以你提供的回答风格，我的当前水平大致对应几年经验"。
```

### 场景 2：用 AI 做模拟面试（含追问）

```text
请扮演一个 2026 年某大厂资深面试官，对我进行 30 分钟技术面试。
规则：
- 一次问一个问题
- 我答对就追问 2 层深度，答错就给提示但不直接给答案
- 至少包含 1 道 AI 系统设计题、1 道 AI 协作问题（"你怎么用 Cursor 的"）
- 结束时给出"如果是我评分会给几分"+ 改进建议
从 ConcurrentHashMap 1.8 的并发控制开始。
```

::: tip 💡 关键

> 模拟面试的价值**不在 AI 问了什么**，而在**你练习了"在压力下组织语言"**。建议**关掉文字输入，用语音对话**，模拟真实电话面试。

:::

### 场景 3：用 AI 做知识串联（构建知识图谱）

```text
请帮我画出"从浏览器输入 URL 到页面展示"涉及的所有知识点的 Mermaid 思维导图，
每个节点标注：① 面试追问的常见 2 层问题；② 涉及的协议/技术标准；③ 2026 年的新变化（如 HTTP/3、QUIC、ESNI、RSC）。
```

### 场景 4：用 AI 做项目复盘

```text
以下是我做的一个项目的详细描述：
[粘贴项目描述]

请按 STAR-AI 模板帮我梳理面试讲法：
1. 项目最有"含金量"的 3 个技术决策是什么
2. 面试官可能追问的 5 个问题
3. 我应该提前准备的 3 个"故意留白"的引导点（引诱面试官追问我擅长的方向）
4. 如果项目用了 AI 工具，我应该如何区分"我做的"和"AI 做的"
5. 这个项目可能暴露的弱点是什么，怎么提前规避
```

## 不同复习阶段的 AI 使用策略

| 阶段 | 你自己先做什么 | AI 最适合做什么 | 必须避免 |
|------|------|------|------|
| **摸底期**（第 1 周）| 过大纲，标出不确定的知识点 | 出诊断题、评估薄弱方向 | 直接让 AI 出"完美复习计划" |
| **精读期**（第 2-3 周）| 深入学习每个知识点，**动手写代码** | 解释原理、举例对比、生成对抗练习 | 跳过手写直接看 AI 解释 |
| **强化期**（第 4-5 周）| 刷题 + 项目复盘 | 模拟面试追问、识别表达漏洞 | 让 AI 替你"想"答案 |
| **冲刺期**（最后 1 周）| 反复讲项目 + 手写核心代码 | 录音转文字找口头禅、给鼓励 | 临时抱佛脚学新框架 |

::: warning ⚠️ 三件 AI 帮不了你的事

> ① **手写代码的肌肉记忆**——双指针/二分边界要手动写到不假思索；
> ② **现场临场反应**——面试官变化追问时的快速组织能力；
> ③ **真实项目经验的复盘**——AI 只能润色，不能替你回忆"那个 bug 是怎么定位的"。

:::

## 反 AI 作弊：远程面试新规则

远程面试可能采用以下一种或多种规则，具体以招聘方事先说明和当地法律/隐私要求为准：
- ① 共享屏幕或指定窗口
- ② 打开摄像头
- ③ 在线编程平台限制复制粘贴或外部工具
- ④ 要求口头讲解思路

**应对**：尤其是基础算法和 SQL，要练到不需要提示也能完成；开始前主动确认 AI、搜索、文档和粘贴是否允许，遵守规则并保护个人隐私。

## 看到什么就先想到这类

- **"你怎么用 AI 提升效率？"** → 准备 3 个具体场景 + 量化数据 + 1 个踩坑案例
- **"AI 写错怎么办？"** → 单元测试 + Code Review 双闸门 + 关键路径手写
- **"设计一个 RAG 系统"** → [RAG](./rag) 完整章节
- **"现场用 Cursor 写代码"** → 先列需求 / 写测试 / 加约束 / 逐行 review / 跑测试
- **"项目里 AI 做了多少？"** → STAR-AI 模板，明确"决策、架构、核心算法是我，样板和文档是 AI"
- **"反 AI 共享屏幕面试"** → 平时刷题就关掉 Copilot，练真本事

## 持续学习的最佳习惯（2026 版）

1. **每天 30 分钟手写题**（不开 AI），保持基础肌肉记忆
2. **每周 2 个真实小项目**（用 Cursor 完整流程：需求 → 拆解 → 实现 → review → 测试）
3. **每月 1 篇深度博客**（项目复盘 + AI 协作心得，是简历最好的加分项）
4. **关注**：Anthropic / OpenAI 官方博客、ArXiv 每日精选、HackerNews 周榜、国内的 [掘金 AI 圈](https://juejin.cn) / [InfoQ](https://infoq.cn)
5. **建立知识库**：本地 Obsidian + Cursor @Docs 把所有笔记做成你的 RAG 系统，**自己的知识 + AI 的检索 = 复合能力**
