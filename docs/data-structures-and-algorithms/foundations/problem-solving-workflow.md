# 一般流程

<span class="dig-tag dig-tag--category">基础知识</span> <span class="dig-tag dig-tag--easy">⭐ 入门</span> <span class="dig-tag dig-tag--hot">🔥 高频</span>

::: tip 💡 核心要点
第一遍刷题最怕的不是不会，而是不知道该怎么下手。真正有效的一刷，不是直接看答案，而是按固定顺序把题目拆开：读题、暴力解、目标复杂度、实现、复盘。
:::

## 概念

- 一刷题的目标不是“把题做掉”，而是建立判断框架。
- 第一遍不会很正常，但你必须知道自己卡在了读题、建模、实现还是复杂度判断。
- 只要第一次流程稳定，后面二刷、复盘和迁移都会轻松很多。

## 怎么处理

### 一刷题的固定顺序

1. 先完整读题，明确输入、输出、限制条件和边界。
2. 先写出最直接的暴力解，不要一开始就强求最优。
3. 再问自己目标复杂度是多少，能不能从暴力解继续优化。
4. 实现时先用 Java 或 C++ 写出最稳的版本，再考虑压缩写法。
5. 做完后记录：这题属于哪一类，我最开始卡在了哪里。

### 做不出来时怎么办

1. 先确认自己有没有把样例手推清楚。
2. 再确认自己是不会建模，还是不会写代码。
3. 最后再去看题解，而且只先看思路，不要先抄代码。

## 典型实例

| 阶段 | 你应该做什么 | 目标 |
|------|------|------|
| 读题阶段 | 画输入输出关系，补充边界样例 | 读懂题 |
| 暴力阶段 | 写最直接的思路 | 建立问题感觉 |
| 优化阶段 | 看能否降到 $O(n)$、$O(n \log n)$ | 建立复杂度意识 |
| 复盘阶段 | 记录题型、触发信号、易错点 | 建立迁移能力 |

## 走题示例：以 [LC 3](https://leetcode.cn/problems/longest-substring-without-repeating-characters/) 为例

上面是原则，这里是原则的具体演示。拿一道中等题“无重复字符的最长子串”走一遍五个阶段：

### 阶段 1：读题与准确化

- **输入**：字符串 `s`，长度 0–10⁵
- **输出**：无重复字符子串的最大长度（返回 int）
- **边界样例**：空串 → 0；全重复 `"aaa"` → 1；全不重复 `"abc"` → 3
- **实现约定**：子串是连续的，不是子序列；下方数组版显式假设 ASCII。若输入允许任意 Unicode，不能继续用长度 128 的频率数组。

### 阶段 2：暴力解

- 枚举所有子串 `[i, j]`，检查是否无重复，取最大长度
- 复杂度：$O(n^3)$ 枚举 + 检查，n=10⁵ 下 10¹⁵ 操作→超时是肯定的，但**它是正确的**。在面试中先说这个能充当安全网。

### 阶段 3：定复杂度上限 + 识别信号

- n=10⁵ → 需要 $O(n)$ 或 $O(n \log n)$
- 信号：**连续子串** + **状态可增量维护**（加入一个字符、移出一个字符都是 O(1)）→ **滑动窗口**
- 窗口状态：哈希集/频率数组 记录窗口内字符是否出现
- 求最长 → 不合法时收缩，合法时更新答案（while 外更新）

### 阶段 4：实现

```java
public int lengthOfLongestSubstring(String s) {
    int[] freq = new int[128];
    int left = 0, ans = 0;
    for (int right = 0; right < s.length(); right++) {
        freq[s.charAt(right)]++;
        while (freq[s.charAt(right)] > 1) {     // 不合法：收缩到重新合法
            freq[s.charAt(left)]--;
            left++;
        }
        ans = Math.max(ans, right - left + 1);  // 合法后更新答案
    }
    return ans;
}
```

## 从“会写模板”到“能证明模板适用”

### 循环不变量：写代码之前先说一句始终成立的话

无重复子串的窗口算法在收缩完成后满足：`[left, right]` 内没有重复字符，`left` 不回退。加入新字符只可能增加该字符的重复，收缩直到重新合法；每个字符最多被加入、移出一次，因此内层 while 不使总复杂度变成平方级。

但“连续子数组”本身不是滑动窗口的充分条件。例如求和不超过 1 的最长区间，输入 `[3, -2]`：若看到 3 就永久移走左端，会错过和为 1 的整个数组。允许负数后，窗口和不再随扩张单调增加，应重新考虑前缀和、单调结构或其他方法。

| 算法 | 要说清的不变量/适用条件 | 常见反例 |
|------|------------------------|----------|
| 二分答案 | 判定函数在搜索区间具有单调性 | 只因为“求最小值”就二分，判定实际不单调 |
| 双指针/窗口 | 每个边界为何可以永不回退 | 负数破坏窗口和单调性 |
| BFS | 首次访问得到最短边数，边权相同 | 带不同权重时直接把边数当总代价 |
| 贪心 | 局部选择可通过交换论证保留最优解 | 只通过几个样例就断言贪心正确 |
| DP | 状态足够表达后续决策需要的信息 | 状态遗漏“是否使用某次机会”等历史条件 |

### 二分示例：统一使用半开区间

任务是找到非递减数组中第一个不小于 target 的位置，不存在则返回数组长度。循环维护 `[0, left)` 全部小于 target，`[right, length)` 全部不小于 target，未确定区域是 `[left, right)`：

```java
public static int lowerBound(int[] values, int target) {
    int left = 0;
    int right = values.length;
    while (left < right) {
        int middle = left + (right - left) / 2;
        if (values[middle] < target) {
            left = middle + 1;
        } else {
            right = middle;
        }
    }
    return left;
}
```

输入约定为非 null 且已排序；空数组返回 0。每轮严格缩小未确定区间，`middle` 不越界；当左右边界相等，两个已确定区域之间的位置就是答案。不要在同一个模板中混用 `[left, right]` 的终止条件和 `[left, right)` 的更新方式。

## 面试现场的测试顺序

1. **最小输入**：空、单元素、两个元素，先击中下标和终止条件。
2. **结构边界**：全相等、严格递增/递减、重复最值、环、断开的图。
3. **数值边界**：负数、零、整型极值；比较器不要写可能溢出的 `first - second`。
4. **返回约定**：没找到、多个解、是否允许修改输入、是否必须稳定排序。
5. **复杂度反例**：最深递归、全部哈希冲突的假设、反复复制字符串、数组切片隐含成本。

Java 的 `char` 是 UTF-16 code unit，不等于任意 Unicode 字符或用户感知的字素。字符串题要先明确按字节、code point 还是字素计数；生产文本处理不能直接照搬 ASCII 题解。

### 差分测试与性质测试

保留一个明显正确的小规模暴力实现作为 oracle，固定随机种子生成输入，与优化算法对比。失败时打印 seed 和最小输入，缩减反例；两个实现不能照抄同一段错误逻辑，否则“结果相同”没有独立证据。

对 lowerBound，可用线性扫描比对，并额外检查：返回位置在 `[0, length]`；左侧全小于 target；右侧全不小于 target。对最长无重复子串，检查 `0 <= answer <= length`，对字符做保持相等关系的一一重命名后，答案应不变。

| 常见评价 | 更可靠的验收标准 |
|----------|------------------|
| “样例都过了” | 至少补充一个边界输入和一个会让错误实现失败的反例 |
| “随机跑了一万次” | 说明生成范围、固定 seed、独立 oracle 和失败输出 |
| “代码是 O(n)” | 定义 n，说明每个元素访问次数以及库函数隐藏成本 |
| “AI 说这个解法正确” | 自己给不变量、证明和可执行测试；允许工具时也不跳过验证 |

复盘时记录失败原因，而不只是正确答案：题意误读、状态缺失、边界错误、复杂度误判、实现 API 用错，各自需要不同训练。面试中先给出可工作的保底解，再明确优化依据，优于在没有证明时反复替换模板。

## 一刷题最容易犯的错误

1. 一上来就看最优解，导致没有自己的判断过程。
2. 只记代码，不记为什么这题属于这一类。
3. 做完题不复盘，第二天又像第一次见。
4. 刷题速度过快，样例都没手推清楚就开始写。
